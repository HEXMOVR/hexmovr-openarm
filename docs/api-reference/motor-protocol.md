# HEXMOVR CAN 通信协议 Rev.3.10b2

本页整理 `HEXmovr电机CAN通信协议_3.10b2.pdf` 中与 OpenArm 集成最相关的内容。完整字段定义、全部命令和通信示例请直接查看原始 PDF。

[下载完整协议 PDF](../../downloads/HEXMovr_CAN_Protocol_3.10b2.pdf)

## 1. 基本通信规则

- CAN 接口默认波特率：**1 MHz**。
- 可配置波特率：1 MHz、500 kHz、250 kHz、125 kHz、100 kHz。
- 当前协议使用 **CAN 数据帧 + 标准帧格式**。
- 数据字节采用**小端字节序**；MIT 运控模式中的特殊位域按照对应字段定义打包。
- 默认设备地址：`0x01`。
- 可配置设备地址：`1–254`。
- `0x00`：广播地址，从机执行命令但不应答。
- `0xFF`：公共地址，所有从机响应，应答 ID 为各自设备地址。
- 除直接使用 `Dev_addr` 外，从机还可识别 `(0x100 | Dev_addr)` 命令；两种情况下从机应答 ID 均为 `Dev_addr`。

### 数据类型

| 标记 | 含义 |
| --- | --- |
| `1u` / `1s` | 1 字节无符号 / 有符号 |
| `2u` / `2s` | 2 字节无符号 / 有符号，小端 |
| `4u` / `4s` | 4 字节无符号 / 有符号，小端 |
| `4f` | 单精度浮点数，小端 |
| `b` | 字节数 |
| `bit` | 位 |

## 3. 状态读取

### `0xAE`：实时状态

请求：DLC = `0x01`，Data[0] = `0xAE`。

响应 DLC = `0x08`：

| Byte | 字段 | 说明 |
| --- | --- | --- |
| `[0]` | 命令码 | `0xAE` |
| `[1]-[2]` | 母线电压 | `0.01 V/LSB` |
| `[3]-[4]` | 母线电流 | `0.01 A/LSB` |
| `[5]` | 工作温度 | ℃ |
| `[6]` | 运行模式 | `0` 关闭；`1` 电压控制；`2` Q 轴电流；`3` 速度；`4` 位置 |
| `[7]` | 故障码 | 位域见下表 |

故障码位定义：

| Bit | 含义 |
| ---: | --- |
| 0 | 电压故障 |
| 1 | 电流故障 |
| 2 | 温度故障 |
| 3 | 编码器故障 |
| 4 | 预留 |
| 5 | 通信故障 |
| 6 | 硬件故障 |
| 7 | 软件故障 |

协议资料说明：除通信故障外，从机检测到其他故障时，会以约 **200 ms** 周期主动上报 `0xAE` 实时状态。

## 4. 常用控制命令

### `0xC0`：Q 轴电流控制

DLC = `0x05`：

```text
Data[0]   = 0xC0
Data[1:4] = Q轴电流，单位 0.001 A，4s，小端
```

资料给出的关系：

```text
Torque = Q-axis current × torque constant
```

### `0xC1`：速度控制

```text
Data[0]   = 0xC1
Data[1:4] = 速度，单位 0.01 rpm，4s，小端
```

### `0xC2`：绝对位置控制

```text
Data[0]   = 0xC2
Data[1:4] = 绝对位置，单位 Count，4s，小端
```

协议规定：**1 圈 = 16384 Count**。

### `0xC3`：相对位置控制

```text
Data[0]   = 0xC3
Data[1:4] = 相对位置，单位 Count，4s，小端
```

例如 90°：

```text
4096 Count = 90°
```

### `0xC4`：最短距离回原点

DLC = `0x01`，Data[0] = `0xC4`。协议说明电机按最短距离回到设定原点，旋转角度不大于 180°。

### `0xCF`：电机失能

```text
Data[0] = 0xCF
```

电机关闭输出并进入自由态。协议说明电机上电后默认处于该状态。

> **安全提示：** `0xCF` 是电机失能命令，不等同于整机安全急停。OpenArm 产品应具有独立、可靠的急停/断电方案。

## 5. CAN 通信超时：`0xCD`

配置帧：

```text
DLC = 0x05
Data[0]   = 0xCD
Data[1]   = 使能：0x00 失能，0x01 使能
Data[2:3] = 时长，单位 ms
Data[4]   = 附加动作
```

默认时长为 `5000 ms`。超时使能且超过设定时长时，协议定义为报通信故障并失能电机；附加动作位还可配置通信故障码不可软件清除、抱闸开关断开等行为。

## 6. 设备地址：`0xBA`

读取：DLC = `0x01`。

设置：DLC = `0x02`，Data[1] 写入设备地址。

协议说明修改地址后需要重新上电或重启才能生效，并且地址配置断电保存。

## 7. MIT 运控模式

MIT 模式使用不同于普通位置/速度命令的单位：

- 位置：rad；
- 速度：rad/s；
- 力矩：N·m。

### `0xEF`：MIT 最大 Kp / Kd

- `Pos_KP_Max`：默认 `500`，最大可配置 `1000`；
- `Vel_KD_Max`：默认 `5`，最大可配置 `100`；
- 配置保存到驱动板，断电不丢失。

### `0xF0`：MIT 最大位置 / 速度 / 力矩

| 字段 | 单位 | 默认值 |
| --- | --- | ---: |
| `Pos_Max` | 0.1 rad | 955 → 95.5 rad |
| `Vel_Max` | 0.01 rad/s | 4500 → 45.00 rad/s |
| `T_Max` | 0.01 N·m | 1800 → 18.00 N·m |

这些是**协议资料中的默认 MIT 参数**，不是 HEXMOVR OpenArm 整机允许的最终运动限制。

### `0xF1`：MIT 实时反馈

响应 DLC = `0x07`：

- `[1:2]`：机械位置 16 bit，对应 `-Pos_Max ~ +Pos_Max`；
- `[3:4]`：机械速度 12 bit，对应 `-Vel_Max ~ +Vel_Max`；
- `[4:5]`：力矩 12 bit，对应 `-T_Max ~ +T_Max`；
- `[6]`：状态信息，Bit0 表示处于 MIT 模式，Bit1 表示系统有故障。

### MIT 控制帧

MIT 控制帧不包含命令码。为了识别该帧，StdID 的最高位 `Bit[10]` 置 1。

例如设备地址 `0x01` 时，协议给出的标准帧 ID 示例为 `0x401` 或 `0x501`。

8 字节数据依次编码：

```text
目标位置 16 bit
目标速度 12 bit
位置增益 Kp 12 bit
速度增益 Kd 12 bit
目标力矩 12 bit
```

从机反馈内容与 `0xF1` 一致。

## 8. 位置计数与角度换算

协议和上位机资料均给出：

```text
1 revolution = 16384 Count
```

因此：

```text
angle_deg = count × 360 / 16384
count = angle_deg × 16384 / 360
```

常用换算：

| 角度 | Count |
| ---: | ---: |
| 45° | 2048 |
| 90° | 4096 |
| 180° | 8192 |
| 360° | 16384 |

## 9. 通信示例

### 读取故障：`0xAF`

发送：

```text
AF
```

响应示例：

```text
AF 00
```

其中 `00` 表示无故障。

### Q 轴电流 1 A：`0xC0`

```text
C0 E8 03 00 00
```

`0x000003E8 = 1000`，乘以 `0.001 A` 得到 `1 A`。

### 速度 100 rpm：`0xC1`

```text
C1 10 27 00 00
```

`0x00002710 = 10000`，乘以 `0.01 rpm` 得到 `100 rpm`。

### 绝对位置 360°：`0xC2`

```text
C2 00 40 00 00
```

`16384 Count = 360°`。

## 10. 协议版本

当前原始资料为 **Rev.3.10b2，2026-06-09**。资料列出的近期版本变化包括 MIT 参数上限配置、位置滤波、梯形曲线控制、设备地址命令以及通信故障等内容。

实际软件适配时，应将协议版本与电机固件版本一起记录，避免不同固件版本之间的字段差异造成误操作。
